# orgh 入門ガイド — ITに詳しくなくても大丈夫

このガイドは、`orgh`(オルグ)というツールを初めて触る人向けに書いています。
専門用語が出てきたときは、その場でカッコ書きの一言説明を添えます。

## 1. orgh は何をしてくれるのか

- orgh は、あなたが書いた「やりたいことのメモ」を、AIでできた小さな会社に丸ごと渡すツールです。
- その会社の中では、計画係(Planner)が仕事を分け、作業係(Worker)が並列で手を動かし、検品係(Reviewer)が仕上がりをチェックし、ダメなら差し戻します。
- 一区切りついたら振り返り係(Retro)が「今回学んだこと」をノート(playbooks。会社の共有ノートのようなものです)に書き残すので、次に頼むときは会社が少し賢くなっています。

## 2. メモを書いてから結果が返ってくるまでの流れ

「小さな会社をまるごと雇う」つもりで読んでください。

1. **あなたがメモを書く。** 「このリポジトリ(コードやファイル一式が入った作業フォルダのことです)のテストを増やしたい」のような、やりたいことの一文でOKです。
2. **計画係(Planner)が仕事を分ける。** メモを読んで、「誰が何をするか」を細かいタスクの一覧に分解します。タスク同士の順番や依存関係(先に終わらせないといけない仕事)も一緒に決めます。
3. **作業係(Worker)が並列で作業する。** 分けられたタスクを、複数のAIが同時並行で手を動かして進めます。同じ作業フォルダを触って衝突しないよう、タスクごとに「作業用の分身フォルダ(worktreeと呼ばれる、gitというバージョン管理の仕組みが提供する機能です)」を用意してから作業することもあります。
4. **検品係(Reviewer)がチェックする。** 各タスクの仕上がりを、あらかじめ決めた「合格条件」と照らして判定します。実際にファイルを読んだりテストを動かしたりして確認します。
5. **ダメなら差し戻し。** 検品で不合格になったタスクは、指摘つきで作業係に戻され、同じ担当がやり直します(会話の続きとしてやり直すので、一から説明し直す必要はありません)。それでも直らない、そもそも計画自体に無理があるという判定が出た場合は、計画係まで話が戻って計画を練り直します。
6. **振り返り係(Retro)が学びをノートに残す。** ひと通り終わると、「今回何がうまくいって何が手間取ったか」を共有ノート(playbooks)に書き足します。次回以降、計画係と作業係はこのノートを読んでから仕事を始めるので、同じ失敗を繰り返しにくくなります。
7. **あなたに結果が返ってくる。** 実行の記録や成果物は保存され、状況を確認するコマンドで進み具合や合否を見られます。

## 3. できること / できないこと

**できること**
- 「メモ1行」からタスク分解・並列作業・品質チェック・やり直しまでを自動で回す。
- 複数の仕事を同時並行で進める(並列実行)。
- 仕事の合否を機械的な基準(ファイルの中身やテストの実行結果など)でチェックする。
- 実行にかかったお金(AIの利用料)を記録し、上限を超えたら止まる仕組みを持つ。
- 危険な操作(orgh自身の中身を書き換えるような作業)の前に、人間の許可待ちで止まる。
- 過去のミッションで学んだことをノートに蓄積し、次回の計画・作業に活かす。

**できないこと**
- 「絶対に安全」「絶対に正しい」ことを保証しない。検品係は「決めた合格条件を満たしているか」しか見ておらず、成果物の中身に悪意がないかまでは審査していない。
- 人間の最終確認なしに勝手に世の中へ公開したり、取り返しのつかない操作を最後まで自動でやりきったりはしない(後述の承認の仕組みがあるため)。
- 秘密情報(パスワードやAPIキーなど)が結果に紛れ込んでいないかを、自動でせき止める仕組みは持っていない。
- 複数人・複数拠点での本格的な同時運用のような大規模な使い方は想定されていない。あくまで一人の持ち場での利用を前提にしている。

## 4. 気をつけること

- **お金がかかる仕組みがある。** orgh は裏でAI(大規模言語モデル)を何度も呼び出して計画・作業・検品・振り返りをさせています。呼び出すたびに利用料が発生する仕組みなので、実行するたびにお金がかかります。使いすぎを防ぐために、全体の上限額・タスク1つあたりの上限額を決めておくことができ、超えそうになると実行中の仕事の完了は待った上で、それ以上の新しい仕事には着手せず止まります。
- **暴走を防ぐ承認の仕組みがある。** 作業の対象が orgh 自身の中身(プログラム本体や、設定・共有ノートの置き場所)に触れる場合、orgh は自動では実行せず、いったん止まって人間の許可を待ちます。この許可は人間が明示的なコマンドを打ったときだけ与えられ、自動起動の仕組みを使っていてもこの許可待ちは省略されません。設定でこの仕組み自体を無効にする手段も用意されていません。
- **任せきりにせず、結果は人間が確認すること。** 検品係のチェックは「決めた合格条件を満たしているか」を見るだけで、成果物の意図や中身の妥当性まで保証するものではありません。実行の記録や成果物は保存されるので、最終的に「本当に狙い通りか」「公開・反映して問題ないか」は必ず人間の目で確認してください。

## 5. 始め方3ステップ

1. **道具をそろえる。** orgh 本体をインストールし、設定ファイル(どこのメモを見るか、誰に作業させるかなどを書くファイル)を自分用に用意します。
2. **メモを1つ書く。** 「やりたいこと」を一文でメモに書くか、コマンドに直接指示として渡します。まずは小さくて確認しやすいお願いから始めるのがおすすめです。
3. **実行して、結果を見に行く。** 実行を始めたら、進み具合や合否を確認するコマンドで様子を見て、最後に成果物を人間の目でチェックします。慣れてきたら、小さなお願いを2〜3回繰り返してから、少しずつ大きなお願いに広げていくと、振り返りノートが育って仕事の質も上がっていきます。
