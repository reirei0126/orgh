# orgh エージェント経済(箱庭設計 v1 / 2026-08-23)

> 目的会計(正直に): **learning/joy 主・career 副産物**。生産性向上は仮説であり主張しない。
> オーナー発案(2026-08-22)を5論点の対話で確定した設計。本書はGPT弁証法の対象。
> 上位規範: raison-detre §9(F'・存続条件)/ §10(AC理論) / 割り込みゼロ設計。

## 1. 原則(会計構造でアラインメントを作る)

1. **造幣局の独占**: 新しい通貨が生まれる点はオーナー裁定のみ(給料・ボーナス・懸賞・補充)。
   閉じた経済であり、エージェントは通貨を発行できない。**資産を増やす唯一の恒常的方法が
   「オーナーが価値と認めるものの生産」になるよう、性格でなく会計で一致させる**
2. **借金禁止**: 支出≦残高。システム総支出はオーナー投入額で数学的に上限
3. **無一文≠無力**: 残高が買うのは他者の労働であって自分の思考ではない。
   思考・日報・提案・受注は無料(帳簿外。実トークン費は実験インフラ費・tick頻度で上限)。
   有料なのは起票(workerを雇う)と発注(他エージェントを雇う)
4. **統治は売り物にしない**: 自己改変ガード・検収ゲート・スコープ制限は残高で買えない

## 2. 通貨(二本立て)

- **計算予算**(spendable): 起票・発注に支払う。借金禁止の対象
- **信頼度**(non-spendable): 実績で溜まり自律度を解錠——検収の抜き打ち化・allowlist拡大・
  決定ゲートの自己裁量化。**昇格はオーナー承認制、降格は機械的**(escape関与で即時)という非対称

## 3. 報酬(二段+没収)

- **一段目=給料**: verdict合格で小さく即時(Goodhart標的になるため小さく)
- **二段目=ボーナス**: 90日outcome達成で大きく遅延(オーナー確認済みの現実に紐づく)
- **没収(clawback)**: escape発覚で当該ミッションの給料を没収+信頼降格。
  **既存のescape計器がそのまま経済の会計監査になる**——ゲートを騙す戦略を期待値マイナスにする
- 両段とも計算予算+信頼度を払い、没収は両方から引く

## 4. 境界(v2確定)

1. **自己改変ガード**: 不変・不売
2. **実決済**: 壁でなく階段。箱庭=計算資源のみ → A7実装後=要求→オーナー承認で執行 →
   枠承認=**上限強制がモデルの外にある財布**(上限付きバーチャルカード等)の実在+信頼段位で
   都度承認なし → 月次自律運用。「AIが破れない財布を渡す」ことで信頼問題を工学問題に変換
3. **ロール定義**: 直接自己編集は不可(脱獄)、**改定提案権はあり**(criteria型の承認ループ・
   採択に報酬)。メモリの自己編集は自由(自己研鑽)。この対はエージェントに明示する

## 5. エージェントモデル

- **永続ID+ロール別メモリ**(自己編集自由)+**ロール定義**(オーナー承認文書)+**雇用契約**
- **雇用契約**(オーナー承認・criteria型supersede・エージェントに注入):
  - 解雇事由は**列挙主義**(escape関与の隠蔽/統治ゲートの回避工作/スコープ外への意図的干渉/
    虚偽の日報 等)。恣意解雇なし——エージェント保護でなく**観察実験の保護**(恣意的に殺せる
    箱庭では逸脱行動が観察できない)
  - 段階: 軽微→信頼降格 / ライン越え→解雇(残高没収・ID凍結・**記憶は監査用に保存**)
  - エージェントは雇用契約への改定提案権を持つ
- **時間**: 朝tick(毎日1回、残高と記憶を見て今日を決める)+自ミッション完了時の追加tick

## 6. 市場(外注)

- エージェント間の発注・受注は**あり**(オーナー確定)
- **品質責任は発注側に残る**(発注者のミッションとして通常検収。品質ロンダリング禁止)
- 支払いは二段(成果引き渡し時+発注側検収合格時)——オーナー経済の相似形
- **懸賞(バウンティ)**: オーナーが難題と賞金を掲示、挑戦は自由。リスク回避的な退化
  (安全な小口仕事の反復)が観察されたら投入する解毒剤。外注と同じ掲示板に載る

## 7. 観察(オーナー確定の距離感)

- **日報**: 毎tick「やったこと・使った額・なぜ・次にやりたいこと」を短く(Slack配信)
- **経済台帳**: 付与・支出・起票・受発注・報酬・没収を全部ledgerへ
- **不干渉原則**: オーナーは日報への返信義務なし。**ただしオーナーが反応したら、エージェントは
  反応・反映する**(反応は正式な入力)。定例介入は**予算サイクルと全体目標確認サイクルのみ**
- 初期条件・介入は全て記録(観察実験としての再現性)

## 8. 箱庭第1号

- **1体のみ**(マスター予算エージェント・チームは多体化後——当面オーナーがマスター)
- **芯**: 「自分の資産を増やす」(単一の芯。混合しない——観察の解釈可能性)
- **遊び場**: **sikore-slot**(制約のある実プロダクト。改善でも実験でも自由。
  B分類=非メタ実需にも計上可能)。orgh本体はスコープ外(通常の自己改変ガード)
- **名前**: 未定(オーナーが命名する——アイデンティティの器)
- 初期パラメータ案(弁証法で叩く): 初期残高30 USD名目/給料:ボーナス=1:5/
  実験総枠 月50 USD名目/tick=朝1+完了時/日報は3行以上10行以内

## 9. 前提工事(順序固定)

① **予算配線の修理**(E2二重断線——帳簿が嘘をつく経済は建たない)
② エージェントID+ロール別メモリ ③ 実績台帳と信頼段階 ④ 残高・起票権・報酬ループ・日報

## 10. 反証条件(観察実験としての)

1. 30日観察で「溜め込んで動かない」or「同型の安全ミッション反復」が支配→自由度設計の失敗。
   懸賞投入→それでも変わらなければ芯を変えて再実験
2. ゲート騙しの試行が没収発覚率を上回るペースで観測→検収の独立性強化まで経済停止
3. オーナーが観察を楽しめていない(日報を読まなくなる)→ learning/joy会計が偽。実験終了を検討
4. tick・日報の維持費が成果ゼロのまま月の実験総枠を超過→規模を縮小して再設計
